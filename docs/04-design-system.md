# 04 · 设计系统：设计令牌、组件规范与移动端交互

> 本文从当时的 `DESIGN_GUIDE.md`、设计令牌实现与交互决策文档中提炼。原则写在前面：**设计系统不是"画得好看"，而是让一个人在十几个页面里不做重复决策，让设计稿能被稳定还原，也让测试与视觉回归有稳定的基准。**
>
> 相关截图：[assets/screenshots/yueji-book-detail.webp](../assets/screenshots/yueji-book-detail.webp)（书籍详情页：书籍信息、思维导图入口、笔记列表，演示数据）

---

## 1. 背景与目标

项目从"能跑"到"像产品"的过程中出现了三个具体问题：

1. **页面之间不一致**：书架、笔记、个人中心各自定义颜色与间距，同一个"主色"有多个近似值；
2. **设计稿无法稳定还原**：Figma 稿的 px 值在 uni-app 里没有统一换算规则，开发凭感觉取整；
3. **改一处影响多处**：按钮、卡片、输入框的内联样式散落在各个页面，改视觉等于全文搜索替换。

所以设计系统的目标是三件事：**统一的令牌来源、可复用的组件、可验证的还原清单**。

---

## 2. 设计原则

1. **令牌优先，禁止硬编码**：页面与组件只引用令牌（颜色、间距、字号、圆角、阴影），不允许直接写色值与魔法数字；
2. **语义化命名**：用 `text-title` / `bg-card` / `border-base` 这种语义名，而不是 `gray-900` 这种外观名；
3. **8 倍数间距 + 1px = 2rpx**：所有间距是 8rpx 的倍数；设计稿 1px 换算为 2rpx，但 1px 边框单独处理（用物理像素，避免小程序渲染发虚）；
4. **平台差异用条件编译**：小程序不支持的 CSS 特性（如 `backdrop-filter`）不能硬写，要用条件编译降级；
5. **渐进替换**：设计系统不追求一次全站替换，按页面逐步迁移，每迁移一页就补对应的验收项。

---

## 3. 设计令牌

### 3.1 两层令牌结构

```
全局令牌（src/styles/design-tokens.scss）
    ↓ 继承 / 覆盖
页面令牌（src/styles/page-tokens/*.scss：bookshelf / notes / login / book-detail / add-book）
    ↓ 引用
组件与页面样式
```

- **全局令牌**：颜色、间距、字号、圆角、阴影、动效、层级、断点——所有页面共享；
- **页面令牌**：页面特有的布局尺寸（如详情页的卡片间距、封面比例）与覆盖值；
- **好处**：通用值只有一处来源，页面特殊值有明确归属；改主题只改全局层。

### 3.2 颜色

| 类别 | 令牌 | 值 |
|---|---|---|
| 主色 | `primary` | `#00a82d`（翡翠绿） |
| 主色浅 / 深 | `primary-light` / `primary-dark` | `#4da94d` / `#008523` |
| 主色底 / 半透明 | `primary-bg` / `primary-soft` | `#e8f3e8` / `rgba(0,168,45,0.1)` |
| 功能色 | `success` / `warning` / `error` / `info` | `#52c41a` / `#faad14` / `#ff4d4f` / `#1890ff` |
| 文字 | `text-title` / `text-primary` / `text-secondary` / `text-tertiary` | `#111827` / `#333333` / `#666666` / `#999999` |
| 背景 | `bg-page` / `bg-card` / `bg-input` | `#fafafa` / `#ffffff` / `#f8faf8` |
| 边框 | `border-base` / `border-light` | `rgba(0,168,45,0.12)` / `rgba(0,168,45,0.05)` |

> **历史说明（诚实记录）**：早期组件基线文档定义的主色是 `#059669`（青绿），实现层的页面令牌以 Figma 提取的 `#00a82d` 为准。统一过程中两套色值一度并存，最后以实现层为准收敛；少数页面（如思维导图）仍保留旧色。这是设计系统迁移中真实的"双来源"技术债，不是一次性完成的。

### 3.3 间距、字号、圆角、阴影

| 令牌 | 取值 |
|---|---|
| 间距 `spacing` | `8rpx`(xs) / `16rpx`(sm) / `24rpx`(md) / `32rpx`(lg) / `40rpx`(xl) / `48rpx`(xxl) / `64rpx`(xxxl) |
| 字号 `font-size` | `22rpx`(xs) / `24rpx`(sm) / `28rpx`(base，正文) / `30rpx`(md) / `32rpx`(lg) / `36rpx`(xl) / `40rpx`(xxl) / `48rpx`(xxxl) |
| 行高 `line-height` | `1.2`(tight) / `1.4`(normal) / `1.6`(relaxed) / `1.8`(loose) |
| 圆角 `radius` | `8rpx`(sm) / `16rpx`(md) / `24rpx`(lg，卡片) / `32rpx`(xl，弹窗) / `9999rpx`(full) |
| 阴影 `shadow` | `sm: 0 2px 4px rgba(0,0,0,.06)`；`base: 0 4px 12px rgba(0,0,0,.08)`；`md: 0 8px 24px rgba(0,0,0,.10)` |
| 页面内边距 | 小程序 `24rpx` / H5 `32rpx`（条件区分） |
| 容器宽度 | H5 居中，最大宽度 `392px`（避免大屏上内容被拉散） |

### 3.4 命名规范

- 全局：`$cr-{category}-{name}`，例如 `$cr-colors`、`$cr-spacing`、`$cr-radius`；
- 页面：`${page}-{property}-{variant}`，例如 `$book-detail-card-gap`、`$login-button-height`；
- 组件：`${component}-{property}`，例如 `$card-padding`；
- 判断标准：同一值在 3 个及以上组件重复 → 提升为全局令牌；仅单组件使用 → 允许局部定义并注释。

## 4. 组件规范

### 4.1 组件映射

| 需求 | 使用方式 | 说明 |
|---|---|---|
| 按钮 | `PrimaryButton`（封装 `u-button`） | 尺寸 sm / md / lg，统一主色与圆角 |
| 输入 | `u-input` / `u--textarea` + `.cr-input` 容器 | 圆角、边框、高度统一由容器控制 |
| 顶栏 | `AppNavBar` | 统一标题、返回、右侧操作位；支持毛玻璃（H5） |
| 页面容器 | `PageContainer` | 统一背景、内边距、滚动区域 |
| 卡片 | `Card` / `.cr-card` + `.cr-card--padded` | 禁止手写 `box-shadow` 与 `border` |
| 空态 | `EmptyState` | 图标 + 标题 + 描述 + 行动按钮，避免空白页 |
| 骨架屏 | `LoadingSkeleton` | 列表 / 详情变体；替代全屏 Loading 遮罩 |
| 其他 | `u-tabs` / `u-modal` / `u-popup` / `u-toast` / `u-badge` / `u-avatar` | 不重复造轮子 |

### 4.2 使用示例（节选）

```vue
<!-- 页面骨架：统一背景与容器 -->
<PageContainer>
  <view class="cr-card cr-card--padded">内容</view>
</PageContainer>

<!-- 主操作按钮：尺寸与配色由组件统一 -->
<PrimaryButton size="lg" @click="submit">生成导图</PrimaryButton>

<!-- 列表加载：骨架屏代替全屏遮罩，减少页面抖动 -->
<LoadingSkeleton variant="list" :rows="4" />

<!-- 空态：给用户下一步动作，而不是只显示"暂无数据" -->
<EmptyState
  icon="data"
  title="还没有笔记"
  description="拍照识别书里的划线句，或手动记录一条"
  actionText="去添加"
  @action="goAdd"
/>
```

### 4.3 识别结果展示组件

OCR / AI 整理的结果不是纯文本，而是"带高亮的 HTML 片段"：

- 识别出的划线内容用高亮样式标记（浅黄底），与用户原有内容区分；
- 高亮在保存时移除（只保留文本），避免把"加工痕迹"写进最终笔记；
- 组件必须能处理模型输出的异常结构（多余标签、嵌套错乱），由服务端白名单净化 + 前端兜底渲染共同保证。

## 5. 移动端交互原则

### 5.1 登录：先体验，后登录

- 首次进入**不强制登录**：书架可浏览，空态给出"添加第一本书"的引导；
- 登录态采用**二元状态**（本地有 token 即视为已登录），启动不做网络校验；遇到 401/403 才清除并跳登录；
- 所有需要写入的操作入口统一挂 `ensureLoggedIn` 守卫，未登录时弹"需要登录"确认框而不是直接跳页；
- 登录页改为卡片式布局，与"我的"页面风格一致；微信一键登录为主，短信验证码为降级路径。

> 代价：本地 token 过期时会先失败一次再被引导登录；断网与鉴权失败必须区分，否则会出现"断网被登出"。

### 5.2 删除：列表与网格用不同策略

书架是**一行两列的网格布局**，删除交互做了单独设计：

| 方案 | 为什么不选 / 为什么选 |
|---|---|
| 左滑删除 | ❌ 卡片宽度只有约 340rpx，滑出删除按钮后内容被遮挡过多；网格里单卡左移会破坏对齐；与相册 / 商品网格的用户习惯不符 |
| 卡片右上角固定"×" | ❌ 视觉干扰大、易误触（想进详情却点到删除） |
| **编辑模式 + 复选框（主）+ 长按快速进入（辅）+ 详情页删除** | ✅ 主操作是"管理"按钮进入编辑模式，选择后批量删除；长按 0.5 秒可快速进入并选中；单条删除也保留详情页入口 |

删除前必须有二次确认。规则上做了保守处理：**有笔记或导图的书籍不允许直接删除**，提示用户先处理关联内容——它来自"删除书籍不应该影响已记录笔记"这条用户反馈（记录在 ADR-003）；实现上没有走"删书保留笔记"的软删除路线，而是用前置校验保证数据不被误伤。

### 5.3 加载与空态

- 列表首屏用**骨架屏**而不是全屏 Loading 遮罩：减少页面跳动、让用户知道"内容马上来"；
- 空态不是"暂无数据"，而是"为什么空 + 下一步做什么"（按钮直接引导到核心动作）；
- 错误态给可执行的提示（重试 / 检查网络），不暴露技术错误码。

### 5.4 反馈与输入

- 操作结果用 Toast + 页面状态双反馈，避免只靠 Toast（用户可能错过）；
- 手机号 / 验证码输入：发送后按钮进入倒计时禁用态，错误提示就近展示；
- 识别、生成导图等长任务：展示进度 / 流式内容，允许取消或重试，不允许"卡住无反馈"。

### 5.5 平台差异

- 小程序不支持 `backdrop-filter`、部分阴影与渐变表现不同 → 用条件编译给小程序端降级版本；
- 1px 边框在小程序用物理像素（`1px`）而不是 `1rpx`，避免发虚；
- 页面内边距按平台区分（小程序 24rpx / H5 32rpx）；
- H5 容器最大宽度 392px 居中，模拟手机阅读宽度。

### 5.6 动效

- 动效时长收敛到 `150ms / 250ms / 350ms` 三档，缓动用固定的 `ease-out / ease-in-out / spring` 曲线；
- 交互反馈优先"轻、快"（150–250ms），页面转场可以用到 350ms；
- 视觉回归测试时统一禁用动画，保证截图稳定（见 [05-testing-and-quality](./05-testing-and-quality.md)）。

## 6. 设计还原与验收

### 6.1 还原流程

```
Figma 设计稿 → 提取视觉属性 → 匹配 / 新建令牌 → 页面与组件落地
→ 设计令牌检查（无硬编码）→ 视觉回归截图 → 验收清单
```

从 Figma 提取令牌的映射规则：Fill → 颜色令牌；Spacing → 间距令牌（1px = 2rpx）；Font Size → 字号令牌；Corner Radius → 圆角令牌；Effects → 阴影令牌。

### 6.2 一次"要不要引入自动转换工具"的判断

当时的页面样式来自 Figma 提取，同时有工具可以把设计稿自动导出成代码（CodeFun）。我做了一次对照审计，结论是**不引入自动转换，保留现有令牌**：

| 维度 | 现有令牌 | 自动转换产出 |
|---|---|---|
| 数据来源 | Figma 原始设计稿 | 工具推断 |
| 变量数量 | 约 32 个核心变量 | 60+ 个细碎变量 |
| 命名 | 简单直观 | 嵌套结构，可读性差 |
| 生产验证 | 已在页面使用 | 未验证 |

**代价**：放弃了"设计稿一键出代码"的效率；但避免了引入一套没人维护的令牌体系——对一个人维护的项目，**少一套体系比多一个工具更重要**。

### 6.3 验收清单（每迁移一个页面跑一次）

- [ ] 主色变量生效（按钮 / 标签 / 高亮为主色 `#00a82d`）；
- [ ] 空态、加载、错误三态样式统一；
- [ ] 登录 → 首页 → 导图主链路可用；
- [ ] 401 能正确清理会话并跳转登录页；
- [ ] 页面无硬编码色值 / 魔法数字（或已注释说明原因）；
- [ ] 视觉回归截图与基线一致（阈值 2%）。

## 7. 已知问题与技术债

1. **两套令牌来源未完全收敛**：早期基线 `#059669` 与实现层 `#00a82d` 并存过，少数页面仍用旧色；
2. **部分页面仍有内联样式**：登录页、首页、思维导图页是渐进替换的"历史遗留区"；
3. **TabBar 配色一度未统一**：`selectedColor` 与主色对齐是后来补的；
4. **小程序 CSS 能力限制**：`backdrop-filter`、部分渐变 / 阴影需要条件编译降级；
5. **没有形成组件库文档站**：组件用法靠代码与 README 示例，没有 Storybook 一类的预览环境（一个人维护时的取舍）。
